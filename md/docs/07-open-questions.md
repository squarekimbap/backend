# 구현 전 결정할 것

아래 세 개는 **코드를 쓰기 시작하면 되돌리기 비싸다.** ADR로 먼저 확정할 것.

## 1. 서버를 두는가 — 결정됨

로그인이 있고 도시 추가·저장이 기기 간에 이어져야 한다. 서버 없이 가면 로그인이 무의미하고, 만들면 4주에 안 들어간다.

**결정/구현** — Lambda 서버를 사용한다. 인증과 실시간 코스 생성, 정적 카탈로그 API가 구현돼 있다.

## 2. 코스 데이터를 어디 두는가

코스 64개와 사진, 이야기 원고를 어디서 갱신할지에 관한 결정이다.

**결정/구현** — 서버 번들 JSON을 `GET /v1/courses`와 `GET /v1/courses/{id}`로 제공한다. 앱은 응답을 캐시할 수 있다.

## 3. TMAP 경로를 언제 계산하는가

생성마다 호출하면 느리고 비싸다. 경유지가 6곳이면 순서 조합이 많아 호출 수가 급증한다.

**결정/구현** — 큐레이션 코스는 미리 계산한 JSON을 사용하고 생성 코스만 실시간 호출한다. route-options는 Haversine 빔 탐색으로 TMAP을 최대 5회 호출하고 JWT·라우트 진입 기준 22초 예산·KST 일일 3회·분당 6회·동일 생성 입력 완성 응답 5분 캐시를 적용한다. TMAP 경로는 버전 키·약 10m 좌표 정규화·분산 single-flight로 약관상 24시간 미만인 23시간 55분 캐시하고 Google 고도 결과는 별도 장기 캐시하지 않는다. 앱 UUID `Idempotency-Key`와 요청 지문의 날짜 독립 상태 원장을 일일 쿼터와 원자적으로 예약하고, 실행 중 중복은 409(`Retry-After: 8`)로 막는다. 모든 HTTP 시도와 500/502 뒤 실제 재실행은 분당 상한에 포함한다. 완료 응답은 압축해 5분만 재생하고 이후 동일 키는 410으로 종료한다. 500/502 실패는 실행 소유자만 단일 트랜잭션으로 일일 횟수를 환불한다. 환불한 토큰은 카운터에서 제거하며, 향후 완주 시 보너스 1회를 더할 수 있게 날짜별 원자 카운터를 사용한다.

아래는 병행 확인 항목이다.

### 오디오 가이드 활용신청과 실데이터 검증

공식 Odii `storyLocationBasedList`가 위치·음성 URL·대본·재생시간을 제공하는 것은 명세로 확인했다. 서버 연동도 구현했다. 공공데이터포털에서 `관광지 오디오 가이드정보_GW` 활용신청 후 `TOUR_AUDIO_ENABLED=true`로 켜고, 실제 키로 응답·음원 재생·라이선스를 검증해야 한다.

### 사진 촬영자 표기

위키미디어 공용은 대부분 CC BY-SA로 촬영자와 라이선스 표기가 필요하다. 현재 캡션과 링크만 있어 불완전하다. 각 파일 페이지에서 확인 필요.

### 위치기반서비스사업 신고

개인위치정보를 다루므로 방통위 신고 대상. 소상공인은 개시 후 1개월 유예가 있지만 서류 준비에 시간이 걸린다.

### 러닝 화면 야외 가독성

어두운 테마는 직사광선에서 잘 안 보인다. 러닝 화면만 라이트로 하거나 밝기를 올리는 처리가 필요할 수 있다. **실기기로 밖에 나가봐야 판단된다.**

### 큐레이션 코스 경로 — 완료

64개 전부 TMAP 보행 `polyline`·`guide`와 경로 100m 안 `checkpoints`를 서버 번들에 저장했다. 앱은 `polyline.count >= 2`이면 시작을 허용하고, GPX 공유는 `GET /v1/courses/{id}/gpx`의 GPX 1.1 Track 파일을 그대로 사용한다.

### 계정 삭제 시 Apple 토큰 폐기

App Store 심사 지침 5.1.1(v). 화면은 있으나 실제 토큰 revoke 처리가 필요하다.
