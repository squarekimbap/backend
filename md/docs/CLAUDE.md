# 어디 뛰지 — AI 개발 가이드

이 저장소는 iOS 앱 **어디 뛰지**(코드네임 Dali)를 개발한다.
여행지에서 관광지를 지나는 러닝 코스를 만들고, 체크포인트 100m 안에 들어가면 그곳의 이야기가 재생된다.

## 작업 전 반드시 읽을 것

| 파일 | 언제 |
|---|---|
| `01-design-system.md` | UI를 만들 때 — 색·서체·크기는 여기 값만 쓴다 |
| `03-screens.md` | 화면을 만들 때 — 해당 화면 섹션만 읽어도 충분하다 |
| `06-copy.md` | 문구를 쓸 때 — 내부 용어를 화면에 노출하면 안 된다 |

## 절대 규칙

1. **색을 새로 만들지 않는다.** `01-design-system.md`의 토큰만 쓴다.
   앱은 색을 만들지 않고, 색은 사진과 카카오 버튼만 들여온다.

2. **상태를 색으로 구분하지 않는다.** 빈 링 = 미완료, 채운 원 = 완료.
   이것이 이 앱의 고유 어휘다.

3. **개발 용어를 화면에 쓰지 않는다.** "검증", "데이터", "확보", "실측", "열림", "polyline" 금지.
   `06-copy.md`의 매핑을 따른다.

4. **트리거 규칙을 바꾸지 않는다.** 반경 100m · 정확도 50m 게이트 · 2회 연속 · 세션당 1회 · 출발 300m 보류.
   프로토타입에서 검증한 값이다. 새로 설계하지 말고 그대로 옮긴다.

5. **`routed == false`인 코스는 시작·GPX 내보내기를 잠근다.**
   대략적인 경로가 파일로 나가면 사용자가 믿고 따라간다.

6. **잠긴 이야기의 내용을 노출하지 않는다.** 제품의 핵심이다.
   여기서 다 읽을 수 있으면 달릴 이유가 사라진다.

## 판단 기준

문서와 프로토타입이 어긋나면 **프로토타입을 따른다**.
`prototype/eodi-run-prototype.html`을 브라우저에서 열어 확인할 수 있다.

## 화면 만들 때 프롬프트 예시

```
docs/03-screens.md 의 "러닝 중" 섹션과 docs/01-design-system.md 를 참고해서
RunningView.swift 를 만들어줘. 실측 좌표를 그대로 쓰고,
동작 규칙의 트리거 조건을 정확히 지켜줘.
```
